describes every column as received; derived columns added by the pipeline (for example the outlier flag and the
pack size in grams) are documented in \cref{sec:preprocessing}.

Net\_Sales\_BDT & decimal & Gross sales $-$ discount \\

\end{table}

\chapter{Reproducing and Deploying the Project}\label{app:reproduce}
This appendix gives the steps needed to rebuild every result, figure and table of the report from the raw data,
and to deploy the dashboard and website free of charge.

\section{Project structure}\label{app:structure}
The repository is organised as follows; every folder marked as generated is rebuilt by \texttt{run\_pipeline.py}.
\begin{lstlisting}
dan_cake_project/
  run_pipeline.py          one command for the whole framework
  src/dancake/             config, data, eda, features, forecasting, classification,
                           clustering, anomaly, insights, export, website
  dashboard/app.py         Streamlit dashboard
  data/  processed/ warehouse/ dashboard/   generated data
  outputs/ metrics/ tables/ models/          generated results
  report/  main.tex, chapters/, figures/, tables/, generated/
  docs/                    project website (GitHub Pages)
  algorithms/              one lesson per algorithm (01-09), common.py,
                           export_to_report.py, outputs/
  tools/                   capture_screenshots.py (report screenshots)
  01_...07_*.py            hands-on preprocessing and predictive-analytics scripts
  sql/  tests/  guides/
\end{lstlisting}


\section{Running locally}
\begin{lstlisting}[language=bash]
python -m venv .venv
.venv\Scripts\activate            # Windows  (source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt
python run_pipeline.py            # about 20 minutes
python -m pytest tests            # automated tests
streamlit run dashboard/app.py    # open http://localhost:8501
\end{lstlisting}

\section{Running the algorithm study}
Each experiment of \cref{ch:algorithms} is a separate script. They can be run in order, or step by step in
VS Code by clicking \emph{Run Cell} above each \texttt{\# \%\%} marker. The export script then refreshes the
tables, numbers and figures of \cref{ch:algorithms}.
\begin{lstlisting}[language=bash]
python algorithms/01_linear_regression.py      # ... up to 09_kmeans_clustering.py
python algorithms/export_to_report.py           # update report tables and numbers
python tools/capture_screenshots.py             # refresh dashboard screenshots
                                                # (dashboard running on port 8510)
\end{lstlisting}

\section{Free deployment (as carried out)}
\begin{enumerate}
  \item A public GitHub repository was created and the project pushed (\repo). The raw CSV and intermediate
        data are excluded by \texttt{.gitignore}; the small dashboard data are included.
  \item \textbf{Dashboard:} in Streamlit Community Cloud, signed in with GitHub, \emph{Create app} $\rightarrow$
        \emph{Deploy a public app from GitHub}; repository \path{sumon-cse83/dan-cake-analytics}, branch
        \texttt{main}, file \texttt{dashboard/app.py}, app address \texttt{dan-cake-analytics}. The app is live
        at \dashurl.
  \item \textbf{Website:} GitHub Pages was enabled for branch \texttt{main}, folder \texttt{/docs}. The site is
        live at \siteurl.
  \item The website was regenerated with the real links (run inside \texttt{src}), then committed and pushed:
\begin{lstlisting}[language=bash]
python -m dancake.website --dashboard-url https://dan-cake-analytics.streamlit.app \
                          --repo-url https://github.com/sumon-cse83/dan-cake-analytics
\end{lstlisting}
  \item Every later \texttt{git push} to \texttt{main} redeploys both the dashboard and the website
        automatically (\cref{fig:cicd}).
\end{enumerate}

\section{Re-using the framework for another project}
Only \texttt{src/dancake/config.py} (paths, column names, train/test dates) and the column lists in the
feature functions need to change for a new sales dataset. The structure, namely validation, cleaning,
warehouse, EDA, leakage-safe features, benchmarked models, dashboard, insights and generated report, transfers
unchanged to other domains such as inventory, finance or customer analytics.
